# Backend

ASP.NET Core 10 API, layered the same way as opalsnz: `Opalsnz.Accounting.Api` (controllers,
`Program.cs`, auth), `Opalsnz.Accounting.Db` (EF Core + MySQL), `Opalsnz.Accounting.Model` (DTOs/options),
`Opalsnz.Accounting.Service` (business logic, auth, mapping).

## Prerequisites

- .NET 10 SDK
- Docker (for local MySQL via `../db/docker-compose.db.dev.yml`)

## Local setup

1. Start the dev database and apply Flyway migrations:

   ```powershell
   cd ../db
   docker compose -f docker-compose.db.dev.yml up -d
   ```

2. Run the API (uses `appsettings.Development.json`, already configured for the local dev DB above):

   ```powershell
   cd Opalsnz.Accounting.Api
   dotnet run
   ```

3. Default dev login (local dev database only — **do not use in production**):
   - Username: `owner`
   - Password: `ChangeMe123!`

## Regenerating EF Core models from the database

Schema changes are made as Flyway SQL migrations under `../db/opalsnz_accounting/sql`, then the EF Core
models are regenerated by scaffolding from the database (db-first, matching opalsnz):

```powershell
cd Opalsnz.Accounting.Db
cp scaffold-config.template.json scaffold-config.json   # first time only, then edit credentials
./scaffold-db.ps1
```

`scaffold-config.json` is git-ignored — it holds real (even if only local) database credentials.

## Configuration

Secrets (`Jwt:SigningKey`, `SingleUser:PasswordHash`, `ConnectionStrings:DefaultConnection`,
`Cors:AllowedOrigins`) are empty in `appsettings.json`/`appsettings.Production.json` and must be
supplied via environment variables in any deployed environment — see
[docs/architecture-decisions.md](../docs/architecture-decisions.md).
